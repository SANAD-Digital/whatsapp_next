# أحداث البوابة (wa-admin): التعديل والتفاعل والحذف

**إلى:** فريق البوابة wa-admin · **من:** فريق منصة سند للواتساب وتطبيق WhatsApp Next · **التاريخ:** 2026-10-01

## المشكلة باختصار

عندما يعدّل شخص رسالة، أو يتفاعل معها بإيموجي، أو يحذفها، تصلنا من البوابة كرسالة واردة عادية فارغة:

```json
{
  "event": "message.received",
  "chat": "120363412859816421@g.us",
  "from": "39883435471066@lid",
  "sender_number": "967777667663",
  "message_id": "AC5387DDFBDF0A0533FC9F6CDF33FCBD",
  "text": "",
  "has_text": false,
  "is_edit": false,
  "is_from_me": false,
  "timestamp": 1790731592
}
```

هذا مثال حقيقي لتعديل رسالة في مجموعة بتاريخ 2026-09-30، وصل بعد الرسالة الأصلية «رسالة قبل التعديل» بثماني ثوانٍ. لا يوجد فيه:
- النص الجديد؛
- معرّف الرسالة التي عُدِّلت؛
- ما يقول إنه تعديل (`is_edit` قيمته `false`).

التفاعلات تصل بنفس الشكل الفارغ. فلا المنصة ولا التطبيق يستطيعان معرفة ما حدث، فتظهر للمستخدم «رسالة نصية» فارغة.

## ما فحصناه في البوابة نفسها (2026-10-01)

- **الويبهوك يعمل.** جهازنا (`5a29e239-…`) له ويبهوك واحد نشط (رقم 77) منذ 2026-09-30، يشير إلى مستقبِل المنصة. الأحداث المسجّلة فيه 11 حدثاً، منها `message.reaction`. والرسائل وإيصالات التسليم والقراءة تصلنا فعلاً.
- **`message.reaction` مسجّل لكنه لم يُرسل قط.** قبلت البوابة الاشتراك فيه، لكن التفاعل في الاختبار وصل كـ `message.received` فارغ.
- **لا يوجد `message.edited` ولا `message.deleted`** في أي مكان نصل إليه: لا في قائمة أحداث الويبهوك، ولا في واجهة الإدارة. صفحة الويبهوك فيها ثلاث فئات عامة فقط: الرسائل والحالة وكود QR.
- **لا يوجد مسار يعرض الأحداث المدعومة:** `GET /api/webhooks/events` يُقرأ على أنه `/webhooks/{id}` ويعيد `invalid webhook_id`.
- **الإحصاءات العامة للبوابة:** 32 ويبهوك نشطاً، و204 عمليات تسليم، منها 61 فاشلة (نسبة النجاح 70%). هذه لكل الأجهزة، لا لجهازنا وحده.

الخلاصة: التعديل والحذف غير مدعومين في البوابة. والتفاعل مسجّل بالاسم لكنه لا يُولَّد.

## ما نحتاجه

لكل حدث من الثلاثة أدناه:
- **اسم حدث خاص به** في `event`.
- **معرّف الرسالة الأصلية** التي وقع عليها الحدث، بنفس القيمة التي أعادتها البوابة في `message_id` عند الإرسال أو وصلت في `message.received`.
- **معرّف فريد للحدث نفسه** في `message_id`، ولا يتكرر لحدثين مختلفين.

الحقول المشتركة تبقى كما هي اليوم: `chat` و`from` و`sender_number` و`is_from_me` و`timestamp`.

### 1. تعديل رسالة: `message.edited`

```json
{
  "event": "message.edited",
  "message_id": "AC5387DDFBDF0A0533FC9F6CDF33FCBD",
  "edited_message_id": "AC420AB4CCF3E270EAE678F1C2B67E87",
  "text": "رسالة بعد التعديل",
  "chat": "120363412859816421@g.us",
  "from": "39883435471066@lid",
  "sender_number": "967777667663",
  "is_from_me": false,
  "timestamp": 1790731592
}
```

| الحقل | إلزامي | المعنى |
|---|---|---|
| `edited_message_id` | نعم | معرّف الرسالة الأصلية التي عُدِّلت |
| `text` | نعم | النص الجديد كاملاً بعد التعديل |

إن تعذّر حدث مستقل، يكفي `message.received` بشرط: `is_edit: true` و`edited_message_id` و`text` بالنص الجديد.

### 2. تفاعل بإيموجي: `message.reaction`

```json
{
  "event": "message.reaction",
  "message_id": "AC2DCEC69CEE76893C61AF26B4E03804",
  "reacted_message_id": "3EB0B308FB66F8A37C7CE8",
  "emoji": "👍",
  "chat": "120363412859816421@g.us",
  "from": "39883435471066@lid",
  "sender_number": "967777667663",
  "is_from_me": false,
  "timestamp": 1790731526
}
```

| الحقل | إلزامي | المعنى |
|---|---|---|
| `reacted_message_id` | نعم | معرّف الرسالة التي تفاعل معها |
| `emoji` | نعم | الإيموجي، ونص فارغ `""` عند إزالة التفاعل |

المنصة تدعم `message.reaction` مسبقاً وتربطه برسالتنا الصادرة عبر `reacted_message_id`، فيكفي أن يصل بهذا الشكل.

### 3. حذف رسالة: `message.deleted`

```json
{
  "event": "message.deleted",
  "message_id": "AC91E0...",
  "deleted_message_id": "AC420AB4CCF3E270EAE678F1C2B67E87",
  "for_everyone": true,
  "chat": "120363412859816421@g.us",
  "from": "39883435471066@lid",
  "sender_number": "967777667663",
  "is_from_me": false,
  "timestamp": 1790731700
}
```

| الحقل | إلزامي | المعنى |
|---|---|---|
| `deleted_message_id` | نعم | معرّف الرسالة المحذوفة |
| `for_everyone` | نعم | `true` إذا حُذفت عند الجميع |

## طلب إضافي لإيصالات المجموعات

في المجموعة يصل `message.delivered` و`message.read` مرة لكل عضو، وكلها تحمل نفس `message_id`. نرجو إضافة الحقل `participant`: رقم العضو الذي استلم أو قرأ، حتى نعرف من قرأ الرسالة.

## ملاحظة: ما تم عندنا

المنصة كانت تحفظ معرّفاً عشوائياً بدل `message_id` الذي تعيده البوابة عند الإرسال، فلم تكن إيصالات التسليم والقراءة تُربط برسائلنا. أُصلح هذا بتاريخ 2026-09-30. رد البوابة الحالي عند الإرسال (`{"message_id": "3EB0…"}`) صحيح ولا يحتاج تغييراً.

## كيف نتحقق معاً

نرسل رسالة من التطبيق إلى مجموعة تجريبية، ثم يقوم عضو بالتالي:
- يتفاعل معها بإيموجي؛
- يرسل رسالة ثم يعدّلها؛
- يحذف رسالة.

لكل حركة نتوقع حدثاً واحداً بالاسم الصحيح، ومعرّف الرسالة الأصلية مطابقاً لمعرّفها عند الإرسال أو الاستلام.
