# تسليم التصميم: شاشات الواتساب هَب (Hub Screens)

## نظرة عامة
هذه الحزمة تحتوي على **18 شاشة** من لوحة تحكم "الباشق" لإدارة واتساب (ربط أجهزة، جهات اتصال، مجموعات، قوالب رسائل وإشعارات، أوامر، دوال، حملات، طابور إرسال، رسائل صادرة/واردة، فوترة، إعدادات، ومحاكي واتساب) — بالإضافة إلى مكتبة المكونات المشتركة وطبقة البيانات التجريبية التي تعتمد عليها.

الواجهة كاملة **بالعربية واتجاه RTL**، وتدعم الوضعين الفاتح والداكن.

## عن ملفات التصميم
الملفات هنا **مراجع تصميم مكتوبة بـ HTML** — نماذج أولية تُظهر الشكل والسلوك المقصود، وليست كوداً إنتاجياً يُنسخ كما هو. المطلوب من Claude Code هو **إعادة بناء هذه الشاشات داخل بيئة المشروع الهدف** (React / Next.js / Vue / أي إطار قائم) باستخدام أنماطه ومكتباته المعتمدة. إن لم تكن هناك بيئة قائمة بعد، اختر الإطار الأنسب (المقترح: React + TypeScript + Vite، مع دعم RTL) ونفّذ التصميمات فيه.

كل ملف `.dc.html` يفتح مباشرة في المتصفح لمعاينة الشاشة.

## ترتيب المجلد
```
docs/
├── component/   المكونات المشتركة (Cards, List View, Bulk Send, …)
├── screen/      الشاشات (Hub Screen - *) + التطبيق الكامل WhatsApp Hub App-pro
└── shared/      زمن التشغيل والبيانات التجريبية (support.js, ui-kit.js, hub-*.js)
```
كل ملف يحمّل السكربتات من `../shared/`، و`<dc-import>` يبحث عن المكونات في `../component/`
(`COMPONENT_DIR` في `shared/support.js`). عند إضافة ملف جديد التزم بنفس المسارات ولا تعد الملفات
إلى الجذر.

> ملفات `Hub Page - *` المذكورة في `shared/hub-pages.js` غير موجودة عن قصد: كانت مجرد تجميع
> للشاشات داخل إطار التطبيق، وهذا الدور يؤديه `screen/WhatsApp Hub App-pro.dc.html`.

## مستوى الدقة
**عالي الدقة (hi-fi)**: الألوان والخطوط والمسافات والحالات التفاعلية نهائية. أعد بناء الواجهة بدقة بصرية مطابقة، مع استبدال آلية التنفيذ بأنماط المشروع الهدف.

## بنية الملف الواحد (مهم قبل القراءة)
كل ملف `.dc.html` مبني على صيغة "Design Component":

- `<helmet>` في أعلى القالب: خطوط Google، ومتغيرات CSS للثيم (`:root` و `[data-theme="dark"]`)، وإعادات ضبط بسيطة.
- **القالب**: HTML بأنماط inline فقط، مع فتحات قيم `{{ name }}`، وعناصر تحكم `<sc-for>` و `<sc-if>`، واستدعاء مكونات فرعية عبر `<dc-import name="Cards" …>`.
- **المنطق**: `class Component extends DCLogic` — مثل React class component: `state` و `setState` و `componentDidMount`، ودالة `renderVals()` تُرجع القيم والمعالِجات التي يستهلكها القالب.

عند النقل: `renderVals()` ⇒ جسم دالة المكون في React (متغيرات + `useMemo` + معالِجات)، والقالب ⇒ JSX، و`<sc-for>` ⇒ `.map()`، و`<sc-if>` ⇒ شرط، و`<dc-import>` ⇒ استدعاء مكون.

## التشغيل بدون إنترنت (offline)
مجلد `offline/` (نسخ مستقلة لكل شاشة، 3–4 ميجابايت للملف) **غير مضمّن في هذه الحزمة**. الملف الوحيد
من هذا النوع هنا هو `component/App Shell (offline).html`، ويفتح بالنقر المزدوج بدون خادم.

ملفات `.dc.html` في `component/` و`screen/` هي **مصدر التطوير** — للمعاينة شغّل خادماً محلياً من داخل `docs/` (`python3 -m http.server`) ثم افتح مثلاً `/screen/Hub Screen - Home.dc.html`، لأن الاستيراد بين الملفات لا يعمل عبر `file://`.

### اتفاقية الـ props المشتركة
معظم المكونات تستقبل نفس المجموعة:

- `meta` — كائن يصف المحتوى (العناصر، الأعمدة، البطاقات…). هذا هو المدخل الأساسي للبيانات.
- `handlers` — كائن دوال للإجراءات (`onOpen`, `onEdit`, `onDelete`, `onSend`…).
- `loading` — منطقي، يعرض حالة الهيكل العظمي (skeleton).
- `lang="ar"` و `theme` — اللغة والثيم (`light` / `dark`).
- `density` — `compact` أو `comfortable`.
- `embed` — `true` عند الاستخدام داخل شاشة (يخفي إطار العرض التوضيحي).
- `show-docs` — `false` في الاستخدام الفعلي (توثيق داخلي للمعاينة فقط).

في المشروع الهدف: حوّل `meta` إلى props مُصنّفة بأنواع TypeScript، و`handlers` إلى props دوال مفردة.

## طبقة البيانات
| الملف | الدور |

| `hub-data.global.js` | مولّد البيانات التجريبية: الأجهزة، الجهات، المجموعات، القوالب، الأوامر، الحملات، الرسائل، الطابور، الفواتير. يُعرَّف على `window.HubData` (~44 مفتاحاً) |

## الرموز التصميمية (Design Tokens)

### الألوان — الوضع الفاتح
```
--bg:#F5F7F6   --surface:#FFFFFF  --sunken:#EEF2F0  --border:#E3E8E6  --border-2:#C9D2CF
--ink:#0F1A18  --ink-2:#33423F    --ink-3:#55645F   --ink-4:#62716D
--pri:#0F7A63  --pri-d:#0A6250    --pri-s:#DFF1EC   --pri-sb:#B6DDD2  --on-pri:#FFFFFF
--ok:#1A8B50   --ok-s:#E1F3E8     --ok-i:#16713F    --ok-sb:#B9E2CA
```
`--wn-*` (تحذير) و `--dg-*` (خطر) تتبع نفس النمط: اللون الأساسي، `-s` خلفية خفيفة، `-i` لون النص فوق الخلفية الخفيفة، `-sb` حدّ.

### الخطوط
- الواجهة: `'IBM Plex Sans Arabic', system-ui, sans-serif` — الأوزان 400 / 500 / 600 / 700
- الأرقام والرموز التقنية: `'IBM Plex Mono'` — الأوزان 400 / 500 / 600
- مقاسات شائعة: 11px (تذييل/ملاحظات)، 12–13px (نص ثانوي)، 14px (نص أساسي)، 16–18px (عناوين بطاقات)، 20–24px (عناوين شاشات)
- ارتفاع السطر للنص العربي: 1.7

### المسافات والأشكال
- سلم المسافات: 4 / 6 / 8 / 10 / 12 / 14 / 16 / 20 / 24 px
- حشوة الشاشة: 16px، الفجوة بين الأقسام: 14px
- نصف القطر: 8px (عناصر صغيرة)، 12px (بطاقات ولوحات)، 999px (شارات وأزرار دائرية)
- الحدود: `1px solid var(--border)`

## السلوك والتفاعل
- **RTL**: الجذر `dir="rtl"`. استخدم خصائص منطقية (`padding-inline`, `margin-inline-start`, `inset-inline`) عند إعادة البناء.
- **الثيم**: يُبدَّل عبر `data-theme` على الجذر. خزّن الاختيار وأعِد تطبيقه عند التحميل.
- **ESC** يغلق أحدث طبقة مفتوحة: القوائم المنسدلة أولاً ثم النوافذ المنبثقة. كل نافذة تحتوي زر إغلاق/إلغاء ظاهر.
- **التحميل**: حالة skeleton عبر `loading`، وليس مؤشر دوران في منتصف الشاشة.
- **الفراغ والخطأ**: عبر مكون `States`.
- **التنبيهات**: `Toasts` أسفل البداية (`bottom-start`) بعد كل إجراء ناجح أو فاشل.
- **الحالات (شارات)**: لكل حالة لون خلفية `-s`، لون نص `-i`، ونقطة ملوّنة. غطِّ دائماً حالة غير معروفة بقيمة افتراضية آمنة بدل الوصول المباشر للخريطة.
- **التجاوب**: الشاشات سائلة (`width:100%`)، والشبكات تنكسر إلى عمود واحد على العرض الضيق.

## الأصول
لا توجد صور أو أيقونات خارجية — كل الأيقونات SVG مضمّنة، والخطوط من Google Fonts.

## الخطوات المقترحة للتنفيذ
1. أنشئ طبقة الثيم (متغيرات CSS + مبدّل `data-theme`) ودعم RTL.
2. انقل المكونات المشتركة أولاً: `Data List`، `Toolbar`، `Form`، `Cards`، `States`، `Toasts`، `Overlay Panel`، `Confirm Dialog`.
3. عرّف أنواع البيانات من `hub-data.global.js` ثم اربطها بـ API حقيقي.
4. ابنِ الشاشات بالترتيب: `Devices` ← `Contacts` ← `Message Templates` ← `Campaigns` ← البقية.
